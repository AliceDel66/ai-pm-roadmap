# Agent 工作流产品怎么设计？

## 你将学到什么

这一节讲 Agent 工作流产品。Agent 的价值在于把“理解问题”推进到“完成任务”，但风险也更高，因为它可能读取数据、调用工具、写入系统或触发外部动作。学完后，你能设计一个从建议型开始、逐步走向半自动执行的 Agent 工作流 MVP。

## 先建立直觉

普通 AI 助手像顾问，给你建议；Agent 像助理，可以按目标拆步骤、查资料、填表、发消息，但关键动作仍需要你确认。一个成熟的 Agent 产品不能只展示“自动完成”，还要让用户看见计划、控制权限、确认执行、查看日志。

## 核心知识

Agent 工作流产品核心模块包括：目标输入、任务拆解、工具连接、流程编排、人工确认、执行状态、失败重试、日志审计、结果输出和模板复用。工具可以是搜索、文档、邮件、日历、CRM、表格、工单、Webhook。每个工具都需要权限、入参、出参、错误处理和操作边界。

工作流设计有两种形态：自然语言目标驱动和可视化流程编排。前者适合轻量任务，后者适合企业可控流程。早期产品可以结合：用户用自然语言描述目标，系统生成可编辑步骤，用户确认后执行。

## AI 产品经理视角

Agent 产品最重要的是可控。你要设计人工确认节点，例如发送邮件、修改客户状态、扣费、删除数据等操作必须确认；要设计沙箱或预览，让用户先看到将要执行的内容；要记录每一步输入、输出、工具、耗时和错误。

## 案例拆解

一个“会议后跟进 Agent”可以读取会议纪要，提取待办，生成跟进邮件草稿，创建日历提醒，更新项目表格。MVP 不应直接自动发送邮件，而是先生成草稿并让用户确认。执行完成后展示每一步状态：已提取待办、邮件草稿待确认、日历创建成功、表格更新失败并可重试。

## 方法论

设计 Agent MVP 可以按“低风险三步”：先做建议型，让 Agent 只生成计划；再做半自动，让 Agent 调工具但关键节点确认；最后在低风险任务上尝试自动执行。每一步都要有权限、日志、失败处理和回滚说明。

## 常见误区

第一个误区是直接承诺全自动。第二个误区是工具权限过大。第三个误区是用户看不到 Agent 为什么这样做。第四个误区是没有日志，无法排查错误。第五个误区是把不稳定流程强行自动化，反而降低效率。

## 自测题

### 题目 1

问题：Agent 产品和普通聊天助手的核心区别是什么？  
答案：Agent 能拆解任务并调用工具执行流程。解析：它从回答走向行动。

### 题目 2

问题：为什么关键动作需要人工确认？  
答案：防止误操作、越权和不可逆损失。解析：确认机制是信任基础。

### 题目 3

问题：Agent 日志应记录什么？  
答案：步骤、工具、入参、出参、状态、耗时、错误和确认人。解析：便于审计和排查。

### 题目 4

问题：可视化流程编排适合什么场景？  
答案：企业中需要稳定、可控、可复用的任务流程。解析：它比纯自然语言更可治理。

### 题目 5

问题：Agent MVP 为什么建议从建议型或半自动开始？  
答案：降低风险，同时验证任务拆解和工具调用价值。解析：全自动需要更高成熟度。

## 本节小结

Agent 工作流产品的核心是任务自动化与风险控制的平衡。产品经理要设计计划、工具、权限、确认、日志和失败处理。
