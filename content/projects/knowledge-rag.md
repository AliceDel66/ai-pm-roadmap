# 企业知识库问答系统

## 项目概述

本项目设计一个企业知识库问答系统，帮助员工通过自然语言查询制度、流程、产品资料和客服话术。系统基于 RAG，把文档上传、解析、切分、向量检索、引用来源、权限控制、用户反馈和质量看板组合成完整产品。

## 项目背景

企业资料通常散落在网盘、文档系统、IM 群和内部网站里。新员工不知道去哪找制度，客服和销售需要快速查产品资料，业务人员搜索关键词不准。传统搜索返回文档列表，用户还要自己阅读。企业希望通过 AI 问答提高查询效率，同时保证答案可信和数据安全。

## 目标用户

- 员工：查询制度、流程、产品资料。
- 客服和销售：快速找到统一口径。
- 知识库管理员：上传、维护、更新文档。
- 业务主管：查看高频问题、错误反馈和知识缺口。

## 用户痛点

1. 资料入口分散，用户不知道去哪里找。
2. 关键词搜索不准，表达不同就搜不到。
3. 文档太长，找到后仍要自己读。
4. 答案缺少来源，用户不敢直接使用。
5. 文档权限复杂，不同部门能看的内容不同。
6. 知识更新后旧答案仍被使用。

## 产品目标

1. 高频制度问题平均查询时间降低 60%。
2. 80% 的可回答问题返回明确引用来源。
3. 无答案问题进入知识维护列表，管理员可处理。
4. 权限命中准确，不返回用户无权访问资料。
5. 建立至少 50 个问题的评估集用于版本验证。

## MVP 范围

第一版做：知识库创建、PDF/Word 上传、解析状态、基础切分、向量检索、问答、引用来源、部门权限、答案反馈、无答案列表、基础质量看板。第一版不做：复杂表格解析、多知识库跨域推理、自动同步所有内部系统、精细到字段级权限。

## 核心功能清单

- 管理员端：知识库创建、文档上传、分类标签、权限、解析状态、更新记录。
- 用户端：自然语言提问、答案引用、追问、反馈、收藏。
- 质量运营：高频问题、无答案问题、错误反馈、评估集、回答质量看板。
- 安全权限：部门权限、文档权限、问答日志权限、管理员权限。

## 页面结构

用户端包括知识库选择页、问答页、引用详情、历史记录。管理员端包括知识库列表、文档管理、权限配置、解析状态、质量看板。后台应能查看日志、成本和反馈类型。

## 用户流程

1. 管理员创建知识库并设置权限。
2. 上传文档，系统解析、切分、向量化。
3. 员工进入知识库提问。
4. 系统按权限检索相关片段。
5. 模型基于片段生成带引用答案。
6. 用户查看来源、追问或反馈。
7. 管理员根据反馈更新知识库。

## AI 能力点

涉及 Embedding、向量检索、重排、RAG、引用来源、低置信度拒答、评估集和反馈回流。Prompt 要要求模型只基于检索片段回答，缺少依据时拒答。

## 技术协作点

需要确认 API 入参出参、文件上传大小、解析队列、支持格式、切分策略、向量库元数据、权限过滤位置、流式响应、错误处理、日志字段、模型切换、敏感词和安全策略、模型失败兜底、反馈回流和评估集维护。数据存储包括文档原文、片段、向量、会话、消息、引用和反馈。

## 数据指标设计

- 使用指标：提问量、知识库访问量、文档上传量。
- 效果指标：问题解决率、引用点击率、答案采纳率。
- 成本指标：单问 Token、单问成本、文档处理成本。
- 留存指标：周活用户、复问率、知识库复用率。
- 质量指标：无答案率、错误反馈率、检索命中率。
- 风险指标：越权拦截、敏感内容、过期文档命中。

## 原型设计说明

问答页应突出答案和引用来源，引用可展开原文片段。管理员端要清晰展示文档解析状态、失败原因和更新时间。权限配置页要用矩阵表达部门、角色和知识库关系。

## 交互细节

解析失败显示原因和重试；无答案时拒答并推荐提交问题；引用点击打开原文定位；反馈支持“答案不对”“来源不对”“内容过期”“没有解决”；权限不足时不展示任何相关片段。

## Prompt 设计

系统 Prompt 要求：只能基于提供的资料片段回答；必须引用来源；无法从资料确认时说明未找到依据；不得编造制度、金额、日期或流程；回答结构包含结论、依据、注意事项和下一步建议。

## 风险与边界

风险包括模型幻觉、文档过期、权限泄露、敏感资料进入外部模型、检索不命中、引用错误。边界策略包括权限前置过滤、引用来源、低置信度拒答、文档更新提醒、日志审计和人工反馈。

## 迭代方向

V1 做单知识库问答；V2 增加多知识库、评估集和权限细分；V3 接入内部系统同步、表格问答和企业级审计；V4 增加主动知识推荐和客服/销售场景集成。
